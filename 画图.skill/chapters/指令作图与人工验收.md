# 指令作图 · 人工验收（AI 出图闭环）

> 来源：项目第③课教案（指令作图）＋《进阶班专题课·AI 生成代码必须人工验》v1.0（2026-10-06）＋官方口径素材卡 v1.3。
> 红线口诀：**「一拖一对」——AI 出的图，先拖一下、对一下；你是验收人，不是转发人。**（邱董 08-08：教育判定零容忍。）

## 一、指令作图：提示词三要素

好提示词 = **画什么 + 哪些是可变的 + 怎么看得清**。

| 要素 | 说明 | 范例（y=ax² 图像族） |
|---|---|---|
| 画什么 | 图形/函数表达式、明确数学对象 | 二次函数 y=ax² 的图像 |
| 哪些是可变的 | 参数、可拖动的点——让课件"活" | a 作为可拖动参数 |
| 怎么看得清 | 颜色区分、坐标系、网格、标签 | a>0 / a<0 两种颜色，显示坐标网格 |

- 差：「画个二次函数」→ 可能空心、无参数、无对照。
- 好：「画 y=ax²，a 为可拖动参数，a>0/a<0 用不同颜色，含坐标网格」。
- 出图不符合预期：**改提示词再来一遍，不手动硬改图形**。

## 二、红线动作「一拖一对」（每次 AI 出图必做）

1. 拖生成的参数/自由点 → 图形与数值是否**跟着变**？
2. 对照数学事实核对：拖 a 从 2 到 -2 → 开口是否翻转？|a| 变大是否变窄？数值标签是否与真实几何量一致？
3. 发现错误 → 改提示词重生成；复验后仍错 → 标注"待修"，不进课堂。
4. 留痕：口述/记录一句"我拖了哪里、数值怎么变、对不对"。

## 三、AI 生成组件验收三档 12 项

**第一档：入口可达**
- [ ] ① 打开即用：双击/链接可打开，无白屏
- [ ] ② 依赖完整：单文件拷走功能完整（音效/图片/CDN/字体）
- [ ] ③ 中文正常：中文系统打开不乱码（缺 charset 一行即乱）

**第二档：真机可操作（拖一拖、拨一拨、缩一缩）**
- [ ] ④ 拖拽方向正确（canvas y 轴向下，映射勿反 180°）
- [ ] ⑤ 拨动/滑动判定跟得上，无迟滞错判
- [ ] ⑥ 圈选阈值合理：手绘闭合别要求终点回起点 10px 内（误报"未闭合"）
- [ ] ⑦ 缩放窗口/旋转平板后，已操作内容与统计仍作数
- [ ] ⑧ 高 DPI 平板/投影上线条数字不发虚（devicePixelRatio 适配）
- [ ] ⑨ 窄屏设备（手机竖屏）不横向溢出

**第三档：教学可用（决定能不能进课堂）**
- [ ] ⑩ ★红线 判定**不反相关**：正确做法一定通过、错误做法一定不通过（抽 5 例手算复核）→ 不过**立即停用**，不上课堂
- [ ] ⑪ 统计口径正确：错误次数≠错题数时不误读；角度/时间判定勿用 Math.round 致进位误判
- [ ] ⑫ 离线可分发：断网环境功能完整

## 四、AI 缺陷五类（系统性，不是偶发）

1. 外部依赖（CDN three.js → 断网白屏）
2. 渲染适配（DPR 发虚、固定布局溢出）
3. 交互与判定正确性（拖拽反向、判定反相关——最危险）
4. 数据口径（统计误读、round 进位）
5. 编码环境声明（缺 charset 乱码）

判断律：**「AI 把看得见的数学做对，把看不见的约定做错。」** 验收必须等最后一版，且必须用真机。

## 五、平台联动（作图之后的完整链路）

- **结果形式**：结果对象 → 属性 → 设定 → 结果形式；数值模式（可设小数位数，七年级场景）↔ 代数式模式（根式/分式，八年级场景）。样例：斜边 5.00 ↔ √25。
- **讲解编辑器 + AI 语音**：AI 写讲解稿同样会编出课件上没有的结论 → 红线「**先拖后写、写完再拖**」：拖一遍课件逐条核对讲解里的数值/结论，再生成 AI 语音；文档更新后需重新生成语音。
- **HTML 交互组件**：平台支持导入 **AI / GeoGebra 生成的 HTML**，可「插入交互文档」（讲解）；上传=交付，不是校验——**验只能在上传前做**。
- **命名与分享**：课件命名 `班级-课次-主题`；分享后同桌互开、各拖一次，确认"在我这也能动"。

## 六、作图方法阶梯（官方十讲，自检当前位置）

绘图工具 → 智能画笔 → 构造工具 → 多边形/曲线 → 动态变换(移旋缩) → 自构坐标系 → 参数/动画/按钮 → 迭代。
